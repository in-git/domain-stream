## cms 通用分类模块（/biz/category）

- 背景：后端 `snowy-plugin-biz/.../biz/modular/category` 提供 page / add / edit / delete / detail / downloadImportTemplate / importData / exportData；cms（React 工作台）此前把菜单 `/biz/category`（component=`biz/category/index`）当作 ExternalMenuView 占位页；`backend/snowy-admin-web` 已有代码生成器生成的 Vue 页面。
- 新增 `cms/src/lib/category.ts`：接口封装、实体/枚举/权限判断、二进制下载与 multipart 导入；`cms/src/lib/snowy.ts` 导出 `snowyRequest` 并新增 `snowyFetch`（原始 Response，供 blob/FormData 用）。
- 新增 `cms/src/views/biz/category/index.tsx`（对应 component 路径）与 `dialogs.tsx`：树形层级列表、搜索/模块/状态筛选、前端分页、新增编辑、详情、状态切换、单条与批量删除、Excel 导入/导出/模板下载。
- 接入映射：`types/cms.ts` 的 ModuleKey 增加 category；`lib/menu.ts` 的 DEFAULT_PATHS / MATCHERS（关键词 `biz/category`）/ MODULE_PERM_PREFIX；`lib/router.ts` 的 MODULES；`App.tsx` 的标题与渲染分支、分类页隐藏顶栏快速上传；ExternalMenuView 注释同步。
- 技术决策：后端 `page()` 为生成代码，忽略 searchKey/模块条件，因此列表一次性分页拉全量，在前端做过滤与树组装；编辑接口会整体复制字段，切换状态/编辑时必须提交完整 payload；权限码同时兼容 `bizCategoryAdd` 与 `/biz/category/add` 两种写法。
- 验证：`npm run lint`（tsc --noEmit）与 `npm run build` 均通过。
- 遗留：三个内容编辑器（Video/ImageText/ArticlePages）的分类下拉仍是硬编码常量，未与 BIZ_CATEGORY 联动；业务表 CATEGORY 字段按设计应存分类编码 CODE。

## 移除 cms 的 Node 服务（server.ts）

- 删除 `cms/server.ts`：Express + mock DB（data/cms-db.json）+ /api/* CRUD + 本地文件上传 + Vite middleware + 生产静态托管。前端没有任何代码调用这些 /api/* mock 路由，登录与业务数据全部走 `/snowy` 代理。
- `package.json`：`dev`/`start`/`preview` 改为 `vite` / `vite preview`（当前端口 5000，被占用时 Vite 自动顺延）；`clean` 改为 `rm -rf dist`；移除根依赖 express、dotenv、tsx 与 @types/express（@types/node 保留供 vite.config.ts 使用）。package-lock 已同步，tsx 仅作为传递依赖残留。
- `vite.config.ts`：把 `/snowy` 代理抽为常量，dev 与 preview 共用；支持 SNOWY_HOST / SNOWY_PORT（默认 localhost:91），延续原 server.ts 的可配置能力。
- 保留 `data/cms-db.json`（用户数据文件，虽已无服务端消费）；uploads/ 目录当前已不存在。
- 验证：`tsc --noEmit` 与 `vite build` 通过；`npm run dev` 可由 Vite 直接启动，首页与 `/snowy/auth/b/getLoginUser` 代理均返回 HTTP 200。
